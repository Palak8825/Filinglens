# FilingLens

**Ask Indian listed-company filings anything. Every claim cites the exact PDF page, and code checks each citation before you see it. A deterministic governance red-flag score sits beside the answer.**

Built solo for Arthaton 2026 (AI for personal and business finance). Demo video: _<YouTube link>_

FilingLens is a **hybrid RAG system with an out-of-model hallucination guard**, an **explainable risk engine**, and a **RAG evaluation pipeline**, over 2,924 public NSE/BSE filings for 44 stocks.

- **Hybrid retrieval.** BM25 keyword search and dense embeddings (`bge-small-en-v1.5`) are fused with Reciprocal Rank Fusion, then reranked by a cross-encoder. Questions that name a quarter ("Q2 FY27"), a quarter-end date ("as of 30 September 2026") or a relative quarter ("latest quarter", "QoQ") are hard-filtered to the filings for that period. The UI shows how a relative phrase was interpreted.
- **Hallucination guard.** The LLM must return each claim with a verbatim quote from a numbered excerpt. Code, not the model, checks that the quote actually appears in that excerpt. A citation that fails is dropped and counted. If nothing survives, the answer is marked *Unverified*. A citation that passes links to the rendered PDF page.
- **Explainable risk engine.** Promoter encumbrance, promoter stake drops, auditor resignations, modified audit opinions and low-float price spikes are pure rules over NSE shareholding XBRL, BSE announcements and prices. There is no LLM in this path. Thresholds are printed in the UI, and every flag links to the filing behind it.
- **Evaluation pipeline.** Hand-labelled questions with gold pages, a retrieval ablation (BM25 / dense / hybrid / hybrid + rerank), citation precision with and without the verifier, an abstention test on unanswerable questions, a weak-model arm, and an LLM judge that is a different model from every model it grades.

Not a trading tool. No orders, no broker keys, no portfolio, no money. Research and investor protection only.

## Try it in 10 minutes, no API key needed

The [Releases](https://github.com/Palak8825/Filinglens/releases) page has two options:

| Download | Size | What works |
|---|---|---|
| `filinglens-demo.zip` + `SHA256SUMS-demo.txt` | ~500 MB | Q&A index for 5 stocks (IDEA, PAYTM, RELIANCE, VEDL, YESBANK), every page the example answers cite, red flags for all 44 stocks |
| `filinglens-index.zip` + `filinglens-pdfs-part{1,2}.zip` + `SHA256SUMS.txt` | ~3.5 GB | The full index: 14 stocks, 929 filings, 40k chunks, and every PDF the app can cite |

```bash
git clone https://github.com/Palak8825/Filinglens.git && cd Filinglens
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate  (Python 3.12)
pip install -r requirements.txt
python -m scripts.setup_release path/to/downloads --demo   # or without --demo for the full release
uvicorn api.main:app                                      # http://localhost:8000
streamlit run web/app.py                                  # http://localhost:8501  (second terminal)
```

**Without an API key**, the red flags, the risk screen, the cited page images and the offline selftest all work. Q&A answers the **example questions shown under the question box** from a committed cache (see below). **With a key** (`cp .env.example .env`, set `LLM_API_KEY`; the Gemini free tier works), you can ask anything.

`python -m scripts.selftest` checks chunking, retrieval, period resolution, the citation verifier, the flags and the answer cache offline, in seconds.

### About the cached example answers

`demo/answer_cache.json` holds answers to the demo questions in `demo/questions.json`. They were generated by the same pipeline (retrieve, rerank, LLM, verifier) by `python -m scripts.warm_cache`. Each one is stored whole: the verified citations, the dropped-citation count, and the model that actually answered. In the UI, every cached answer carries a *cached* badge with its date, model and index size, and **Ask live** regenerates it. The cache exists so a judge without a key still sees the full pipeline output, and so the demo survives a free-tier outage. Questions that aren't in the cache are always answered live.

## How it works

```
PDF ─ pymupdf ─ section/speaker-aware chunks (page preserved) ─┬─ BM25 index
                                                               └─ bge-small embeddings → flat float32 index (cosine = one matmul)
question ─ period resolver (Q2 FY27 / 30 Sep 2026 / "latest quarter") ─ hybrid retrieve top-40 (RRF)
         ─ cross-encoder rerank top-8 ─ LLM → JSON {answer, citations[{ref, quote}]}
         ─ citation verifier (quote must be in the cited chunk) ─ answer + page images
NSE shareholding XBRL + BSE announcements/audit reports + prices ─ facts ─ flags.py (rules) ─ risk score
```

Storage is SQLite plus a flat numpy vector file. At this scale (40k chunks, 384 dimensions, about 60 MB) a vector database would not change recall, and a single matrix multiply is well under 100 ms on CPU. The retrieval path (`core/retrieve.py`, `rerank.py`, `verify.py`) is about 270 lines with no RAG framework, so every step can be read and tested.

## AI models and APIs used

| Role | Model / API | Notes |
|---|---|---|
| Answer generation | Google Gemini API, `gemini-3.5-flash-lite` | JSON mode, temperature 0. On a 503 it falls back to `gemini-3.5-flash`, then `gemini-3.1-flash-lite`. The model that actually answered is shown on each answer |
| Eval judge | Gemini API, `gemini-3.6-flash` | A different model from every answering arm, so no model grades itself |
| Eval weak-model arm | Gemini API, `gemini-3.1-flash-lite` | Gives the verifier something to reject |
| Embeddings | `BAAI/bge-small-en-v1.5` (sentence-transformers, local, CPU) | 384-dim |
| Reranker | `cross-encoder/ms-marco-MiniLM-L-6-v2` (local, CPU) | 90 MB; `RERANK=0` disables it |
| Data | BSE corporate announcements API, NSE shareholding-pattern XBRL, Yahoo Finance prices (`yfinance`) | Fetched once and frozen; nothing is called at query time |

Libraries: pymupdf, rank_bm25, numpy, SQLAlchemy/SQLite, rapidfuzz (verifier), FastAPI, Streamlit. There is no LangChain or LlamaIndex. The Anthropic API is supported as an alternative provider (`LLM_PROVIDER=anthropic`) but wasn't used for the reported numbers.

## Red flags

Rules only. Every flag carries its evidence: the filing, the page, and the quote or the filed numbers. Thresholds live in `core/flags.py` and are reported here as-is.

| Flag | Fires when | Source |
|---|---|---|
| `pledge_creep` | encumbered share of promoter holding up ≥ 10pp over 4 quarters | NSE shareholding pattern (XBRL) |
| `pledge_high` | encumbered share of promoter holding ≥ 50% | same |
| `promoter_stake_drop` | promoter holding down ≥ 3pp in one quarter, or ≥ 5pp over 12 quarters | same |
| `auditor_change` | statutory auditor (or a subsidiary's) resigns / casual vacancy | BSE announcements, rules over title + body |
| `audit_qualification` | a results filing contains an SA 705 "Basis for Qualified / Adverse / Disclaimer of Opinion" | audit reports inside BSE results PDFs |
| `float_pump` | max 3-month return in the last year ≥ 100% with public float < 25% | Yahoo Finance prices + NSE public % |

"Encumbered" follows SEBI's definition: pledge, non-disposal undertakings and other encumbrances. The flag text shows the split, because it matters: VEDL's promoter holding is about 100% encumbered with **0% pledged** (facility-agreement covenants), which a pledge-only check would miss. `promoter_stake_drop` is named for what the data shows, not a cause. IDEA's drop is dilution from a Government of India debt-to-equity conversion, which the Q&A explains with citations.

Results on the 44-stock universe: 17 stocks flagged; none of the 13 large-cap controls fires anything.

## Limitations

- **Frozen corpus.** 44 stocks, filings since April 2023, frozen offline. Not live.
- **Coverage.** Q&A covers 14 stocks and skips annual reports (CPU embedding cost). Flags cover all 44.
- **Scanned pages.** About 4.7% of PDF pages are images with no text layer. They aren't OCR'd, so they aren't indexed.
- **The filer's own OCR text.** Some filings carry a text layer made by the company's scanner software. By a heuristic estimate (`python -m scripts.ocr_noise`), about 3.3% of indexed pages, and 4.2% of results pages, contain OCR misreadings such as "financlal" or "crorc". **The citation verifier cannot catch these:** it checks that a quote is present in the filing's text, not that the text is correct. This is separate from the 4.7% of image pages above, which a page-length check can detect and these pages pass.
- **Reasoning limits of the small model.** With reranking on, `gemini-3.5-flash-lite` sometimes refuses cross-quarter comparisons even when both figures are in its excerpts. `gemini-3.5-flash` answers them. The eval's model arm measures this.
- **Verified isn't the same as correct.** An answer can still be wrong when its citations verify, because the verifier checks quote presence, not reasoning.
- **Missing transcripts.** Some companies never file call transcripts (e.g. ITC, RCOM, PCJEWELLER), so their Q&A rests on results and announcements.
- **Heuristic flags.** Red flags are heuristics, not advice. `float_pump` uses Yahoo Finance prices. `rpt_spike` needs annual reports and isn't built. `guidance_miss` was cut because managements mostly guide qualitatively, and a wrong flag citing a real page would undermine the citations.

## Related work

Transcript summarisers exist for US, HK and A-share markets (e.g. BeeBee AI). FilingLens differs in India-specific filing types, page-level citations verified in code, deterministic risk flags, and published evaluation.
